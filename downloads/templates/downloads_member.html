Tell us when a download fails

Your download client knows within minutes whether an NZB actually worked. This site does not — it checks releases against the news servers on a schedule, which finds articles that have expired and cannot see a bad PAR2 set or a post that unpacks to nothing.

One script closes that gap. When a job finishes, it tells us the release and whether it worked. {{if .Recheck}}A failure puts that release at the front of the health queue, so it gets checked against the servers within the hour instead of whenever its turn came round.{{end}}

It sends the job's outcome, its name, and the link it came from. Nothing about your machine, your paths, or anything else you have downloaded.

Set it up

  1. Download the script. Your key and this site's address are already in it — there is nothing to edit.

    report.py

  2. Put it where your client keeps scripts.
    SABnzbd — Settings → Folders → Scripts Folder.
    NZBGet — Settings → PATHS → ScriptDir.
    On Linux or macOS make it executable: chmod +x report.py
  3. Turn it on.
    SABnzbd — Settings → Switches → Post-processing script, pick report.py. To report on only some categories, set it per category under Settings → Categories instead.
    NZBGet — Settings → EXTENSION SCRIPTS, tick it.

One file works for both clients. After the next download, look in your client's history — the script prints what this site said back.

If a report says it could not match the job

A download client reports on a job, and a job has a name rather than a release id. When you add an NZB by its link from this site — which is what Sonarr, Radarr and the download button all do — the link carries the id and the match is exact.

{{if .Matching}}When it does not, we fall back to matching the job's name against your own recent downloads. A client configured to rename jobs heavily can still defeat that, and then the report is answered honestly as unmatched rather than attached to the wrong release. {{else}}When it does not, the report cannot be matched, and it is answered honestly as unmatched rather than attached to the wrong release.{{end}}

Rolling your own

The endpoint is POST {{.Endpoint}}, form-encoded or JSON, taking apikey, status (ok or anything else for a failure), and whichever of id, url, name and filename you have. It answers JSON with a message written to be read by a person.
